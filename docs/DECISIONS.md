# Decisions Log

Record accepted changes to docs/SPEC.md here, newest first.

| Date | Decision | Reason |
|------|----------|--------|
| 2026-10-01 | Melody rendering uses the fluidsynth CLI with a system General MIDI soundfont (`soundfont` in config.yaml; auto-detects FluidR3_GM). There's no pyfluidsynth dependency. `04_melody_reference.wav` is two loops of the main phrase, meaning the first `hook` clip in play order (or the first clip), with quiet block chords on the same instrument, peak-normalized to −3 dBFS. | The spec allowed either renderer, and the CLI is already installed. Chords give the music generator the harmony as well as the tune, and normalizing synthesized music is harmless. |
| 2026-10-01 | Tempo search scores each candidate BPM by how far clip ends sit from a beat (clips start on a bar) plus half the syllable-onset misalignment with the quantize grid. A small penalty for drifting from the preset tempo (0.04 at the edge of the tolerance) means a different tempo has to fit clearly better to win. | Clip starts are bar-aligned by the arrangement, so the end alignment is what matters. On the sample talk the unpenalized search drifted to the edge of the range (119.5 BPM) for a cost barely better than chance. |
| 2026-10-01 | Melody pitch processing: remove the speaker's tuning offset (a weighted circular mean of distances from the semitone grid), then find the key. The order of precedence is `--key`, then a fixed preset tonic, then Krumhansl–Schmuckler detection with a +0.05 bonus for the preset's mode, then the preset's fallback tonic. Next, snap at the preset's strength and shift by whole octaves so the median sits in C4–B4, folding stragglers into G3–C6. Chords are one diatonic triad per bar, chosen by Viterbi with degree priors and bonuses for common progressions. Note names are spelled for the key (E♭ minor's VI is C♭). | Speech is not tuned to A440 semitones, so rounding it without the offset is unstable. Male speech sits one to two octaves below a melody register. Chord names must be readable. |
| 2026-10-01 | `03_selection.json` (schema 2) stores only Claude's raw attempts and which one was chosen. Clean-up (dropping invalid or overlapping clips, count and budget limits) runs in the free `clips` stage, and Claude's own clip IDs are kept unless malformed. Supersedes the renumbering described below. Token estimates were recalibrated to 2.2 characters per token plus 600 for overhead. | On the first live call (Opus 5.5, $0.0548), Claude's arrangement notes referred to its own IDs, so renumbering made them point at the wrong clips. Rule changes in a free stage never force a paid re-run. The live call used 5,972 input tokens against an estimate of 4,802, because timestamps tokenize densely. |
| 2026-10-01 | Dry runs estimate Claude tokens offline: prompt characters / 3 + 400, or 2.6 words/s × 1.6 tokens/word when there's no transcript yet. Output is estimated as 3000 + 250 per clip, to cover adaptive thinking. Estimates include the retry, so the total is a worst case. | `--dry-run` must make no calls, and `count_tokens` is a network call. Rounding up is the safe direction. |
| 2026-10-01 | Claude calls request structured output (`output_config.format` JSON schema) and use server-side refusal fallbacks (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`). Each attempt is priced at the rates of the model that ran it (`usage.iterations`). `claude_fallbacks: false` turns fallbacks off. The default model stays `claude-sonnet-5-5`, per spec section 8. | Structured output guarantees parseable JSON. The Claude API reference recommends fallbacks for current models: a declined request is otherwise simply lost. |
| 2026-10-01 | Claude list prices ship as defaults (Sonnet 5.5 $2/$10, Opus 5.5 $4/$20 per MTok, plus the Opus fallback targets, as of 2026-09-25). `pricing.anthropic` in config.yaml overrides them per model. This supersedes "no built-in prices". | Spec section 9 allows built-in prices as long as config can override them. Without them, every estimate showed "unknown". |
| 2026-10-01 | Stage 3 is two cached stages: `select` (paid, writes `03_selection.json` with every attempt) and `clips` (free, writes `03_clips.json` and `clips/`). Review edits go to `03_review.json`, which is tied to the selection's hash and is an input of `clips`. Claude's clips are renumbered c1..cN in time order, and each clip uses the transcript's own text. | Changing fades or search limits, or editing the order, never repeats a paid call. Review edits survive re-cuts, and a stale review (made for an older selection) is ignored with a warning. |
| 2026-10-01 | Clip cut points may move up to 300 ms before a clip's first word, 400 ms after its last word, and 150 ms into the clip, never past the middle of a neighbouring word (`clips.lead_search_ms`, `tail_search_ms`, `inner_search_ms`). Within that range the cut goes to the quiet stretch nearest the word boundary, a fade length plus 20 ms away from the speech, so the fade lands in the pause. This replaces the spec's flat "about ±150 ms". | Measured on all 103 sentences of the sample talk. With ±150 ms, only 34% of end fades fell below −50 dBFS: Whisper's word ends are early, and speech plus hall reverb decays for several hundred ms after them. With these limits, 95% of end fades (and 96% of start fades) fall below −50 dBFS. |
| 2026-10-01 | The ASR stage checks itself for dropped speech (`whisper.repair_gaps`, on by default). A gap of 3 s or more between words that holds at least 1.5 s of speech according to Silero VAD is widened to the whole segments on either side of it (at most 30.5 s per side). That window is re-transcribed sequentially, and all of its words are replaced. `02_asr.json` lists each repair. | On the full sample talk, batched decoding silently dropped a 29 s chunk of the conclusion (616.6–646.0 s). The same audio transcribes perfectly on its own, so this was a decoder failure, not a speaker skip. The segment right after the hole was damaged too: it held only "In the end," with 1.4 s per word. Re-transcribing just the hole cut the audio mid-sentence, and Whisper hallucinated an ending. Segment boundaries fall in pauses, so widening to them avoids that. |
| 2026-10-01 | Whisper runs batched by default (`whisper.batch_size: 8`). | Measured on a 2-minute excerpt (i7-8750H, turbo, int8): 68 s batched vs 150 s sequential. Same words, word starts within 10 ms median (40 ms at p90), and no hallucinated text where the audio is cut off. |
| 2026-10-01 | The pipeline decodes audio for ASR itself (ffmpeg/soxr, 16 kHz mono) and passes faster-whisper an array. | faster-whisper 1.2.1's own decoder passes PyAV an argument that PyAV 19.0.0 (released 2026-09-29) removed. Doing the decoding ourselves also keeps it consistent with the rest of the pipeline. |
| 2026-10-01 | The ElevenLabs Scribe transcription backend moves to M5. | It's a paid API, and the ElevenLabs docs get read once, together with the music work. |
| 2026-10-01 | Additions to the CLI surface: a `status` command, and `--run` accepts an ID, a unique prefix, a path or `latest` (the default). `--transcript`, `--whisper-model`, `--language` and `--isolate-voice` stick to the run as manifest `options`. New modules: `pipeline.py`, `costs.py`, `errors.py`, `text/`, `backends/transcribe_base.py`, `backends/isolate_*.py`. | Makes the cache state visible, and stops a later command from silently re-running a 15-minute ASR because a flag was omitted. |
| 2026-10-01 | `costs.json` is a JSON array. Entries are only ever appended, and the file is rewritten atomically right after each paid call. | Keeps the spec's file name and "append-only" semantics. |
| 2026-10-01 | `--dry-run` executes nothing, not even free local stages. It prints which stages would run and which are cached, plus paid estimates (from cached artifacts or heuristics), then exits. A paid call without `--yes` needs an interactive confirmation and refuses when there's no TTY. | Predictable and free of side effects, and money is never spent implicitly. |
| 2026-10-01 | Presets get an optional `clips:` block (`count` 5, `min_seconds` 3, `max_seconds` 15, `total_speech_seconds` 60, `fade_ms` 15, plus cut-search limits; see the M2 entry). `--clips N` overrides the count. | Stage 3 needs these targets, and neither the spec's presets nor its config had a place for them. |
| 2026-10-01 | `00_source.wav` is 44.1 kHz **32-bit float**, resampled with soxr (VHQ). It switches to RF64 above 4 GB, and ffmpeg's bitexact flags make it hash-stable. Loudness and peaks are measured with ffmpeg's `ebur128` filter, which streams. | Float keeps MP3 inter-sample overs instead of clipping them, reproducible bytes keep caches valid, and measurement uses constant memory on long talks. |
| 2026-10-01 | The exactness invariant: `clips/*.wav` and the dry `07_mix/stems/speech.wav` are sample-exact slices of the analysis source multiplied by the fade envelope. Gain, EQ, compression and effect sends are applied only on the mix bus. With `--isolate-voice`, the analysis source is `01_clean.wav`, and the manifest records which file clips were cut from. | Resolves the conflict between Goal 3 (bit-exact apart from fades), section 2 ("level changes") and the section 7 processing chain. |
| 2026-10-01 | Alignment flags official text that isn't spoken (captions, headings) as `unspoken` and excludes it from `words` and `sentences`. ASR-only runs of 4+ words become `source: "asr"` sentences. If under 20% of ASR words match the official text, alignment warns and falls back to an ASR-only transcript. | The sample transcript has 12 caption and heading lines. Interpolated timestamps would turn them into fake, selectable "sentences". |
| 2026-10-01 | The pipeline is split into cached sub-stages. The CLI `ingest` runs `ingest` + `isolate`, and the CLI `transcribe` runs `asr` + `align`, which adds the artifact `02_asr.json` (raw ASR output). | Re-aligning, with or without an official transcript, doesn't re-run Whisper. |
| 2026-10-01 | Python ≥3.12 with exact `==` pins for direct dependencies, plus `uv.lock`. torch comes from the PyTorch CPU index, and Intel Macs are excluded from lock resolution. | numpy 2.5 and PyAV 19 need Python 3.12. The Linux torch on PyPI pulls about 3 GB of CUDA libraries, and demucs 4.1 pins numpy<2 on Intel Macs. |
| 2026-10-01 | Voice isolation is implemented in M1 using demucs 4.1.0 (`htdemucs`) as the optional `isolate` extra. The audio is processed in windows with extra context and crossfades, and streamed to disk. | Your choice. Processing in windows keeps memory bounded on hour-long lectures. |
| 2026-10-01 | The default Whisper model is `large-v3-turbo` (the spec's config example said `small`). | Your choice: better names, punctuation and word timings. It takes about 10–20 min of CPU per 13-minute talk and is then cached. |
